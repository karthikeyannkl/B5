BORNTOWIN5 — TARGETED CORRECTIONS + TWO-MOBILE TEST DATA

Changes in this build:
1. Admin A/B/C account rotation is independent for target Levels L4, L5, L6 and L7. Each level cycles A -> B -> C -> A and does not advance another level's counter. Existing L1-L3/global rotation behavior is preserved.
2. Admin Seniority queue calculation is not changed. User-side earnings/completed count now follows the same payment-level classification: REFERRAL_UPGRADE always counts as L2; regular upgrades use the recorded seniorityLevel (fallback to upgrade target). Only receiver-confirmed and admin-approved records count.
3. Admin Seniority accordion keeps the opened/closed state during live refresh so L3-L7 do not collapse unexpectedly.
4. Admin approval is guarded against double-clicks; server validates member/upgrade state before mutating approval flags and returns success for an already-approved transaction.
5. Advanced Referral Upgrade receiver selection is explicitly fixed to L2.
